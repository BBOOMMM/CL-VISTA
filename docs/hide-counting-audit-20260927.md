## 训练代码原因核查

再次核对 xz313 实际训练快照 `cl-vista-seven/code/job29435637` 及训练环境内 DeepSpeed 源码（登录作业 29501611）：

1. `set_cur_task()` 将全部 image/text anchors 设为 `requires_grad=True`。
2. `LLaVATrainer.create_optimizer()` 按 requires_grad 收集参数，没有排除锚点，因此它们进入优化器。
3. 训练采用 ZeRO-2 + CPU optimizer offload。节点 DeepSpeed `runtime/zero/stage_1_and_2.py:527` 为优化器参数创建独立主副本；2554～2558 行在 step 后通过 CPU 低精度缓冲将主副本写回模型参数。
4. 前向中的 `no_grad(): anchor.copy_(...)` 只修改模型侧锚点，没有修改主副本；锚点不参与训练损失，无法通过梯度将统计结果更新至主副本。实际配置 weight_decay=0。

这条代码路径会在 optimizer step 时覆盖手动写入的统计值，与七阶段锚点完全不变的检查点证据一致。这是参数管理方式冲突，不能单独靠调整保存函数或恢复 Parameter 替换语法解决。本轮为实际源码与检查点核查，未重新运行完整 DeepSpeed 训练或改动训练实现。

修复应让锚点/计数器作为非优化器统计状态管理，显式保存加载，使用 FP32 累加和 int64 计数，并处理多 rank 统计汇总。现有训练前向统计代码中也没有显式跨 rank 的特征和与计数归并。
